# AGENTS.md

- `.cursor/rules/*.mdc` — always-on rules: trust zones (ai-companion), Go standards, config, package-docs, join-error-opcodes, no-prerelease-compat.
- Project documentation is written in **English**; when touching a doc in another language, translate the whole file in the same change (see `.cursor/rules/package-docs.mdc`).
- `GLOSSARY.md` — domain terms.
- `docs/architecture.md`, `docs/client-protocol/`, `docs/wire-state-codec.md` — contracts and protocol.
- `docs/adr/` — accepted decisions; `docs/plans/*.md` — work plans; the file list in a plan = the fixed edit scope.
- Before starting a plan written before the latest merged P-commits — verify the contracts (env, wire, ticket, HTTP API) against the actual code; fix plan drift by editing the plan before dispatch.
- Lint: `~/go/bin/golangci-lint run ./...` (config `.golangci.yml`, binary not on PATH); quick test run — `go test -race -shuffle=on -short -count=1 ./tests/...`; CI equivalent — without `-short` (picks up e2e `TestE2E*`, ~2 min in parallel).
- ENet files (`*_cgo.go`, tag `enet`) do not compile on a host without `libenet-dev` — local verification via Docker: `./scripts/enet-verify.sh` (image `zcore-rooms-dev` from `.devcontainer/Dockerfile`; build/vet/test under `-tags enet`). The CI enet smoke job is the final check.
- Editing any file under the `enet` tag (`*_cgo.go`, tagged tests) → mandatory `./scripts/enet-verify.sh build` **and** `vet` before reporting/committing: untagged `go build`/`vet`/lint do not see them, and an error in tagged code would otherwise reach CI. Gopls `No packages found` warnings on these files are expected (gopls runs without `-tags enet` in buildFlags), not an error.
- A new `TestE2E_*` → its own job in `.github/workflows/test.yml` following the `e2e-ws`/`e2e-enet`/`e2e-mixed` pattern (separate status, own timeout): e2e tests are not folded into a shared job.
- Subagents: the task must contain an explicit verification block (commands + expected result); after a code-editing agent reports, the parent runs `go build ./...` before any further steps — the agent may have died mid-edit leaving a half-edited tree.
- "Remove X entirely" tasks (format, env, API): verification greps the term *family*, not the mechanism (P28 example: search `v2|v3|v4|HostIDAny|ENET_LISTEN_PORT`, not just `tokenVersionV2`); leftovers are listed in the report. Run the family check **before dispatch** and include derived terms (env passthrough in deploy/scripts, metric/report fields, helper fields with no readers): every file with a match is either in the plan scope or explicitly deferred with a reason (P33 example: `AuthRoomsDied`, `LOADGEN_POLICY_MIX` in compose survived out of scope until review). "Do not touch" in a plan = do not change behavior; comments referencing renamed/removed concepts are docs and are fixed in the same pass.
